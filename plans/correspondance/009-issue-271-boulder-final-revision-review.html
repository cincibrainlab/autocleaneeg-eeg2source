Senior Review Findings

  1. P1 — Explicit legacy n_jobs=-1 is still broken on the public batch/CLI path. The constructor correctly resolves -1 to multiprocessing.cpu_count(), but cli.process_command passes the literal args.n_jobs as process_batch(..., max_workers=args.n_jobs). process_batch only substitutes self.n_jobs for falsey values, so -1 reaches ProcessPoolExecutor(max_workers=-1) and raises ValueError: max_workers must be greater than 0. The CLI catches that and silently falls back to individual processing. Thus the promised explicit all-core outer semantics do not hold for --n-jobs -1 --batch-processing, and the current test covers only constructor resolution plus forward-worker pinning. Action: normalize the optional batch argument through the same -1/positive validation contract (or pass the already normalized processor.n_jobs from CLI), document -1 in CLI help, and add direct process_batch plus CLI batch regression coverage.
  2. P2 — General failure cleanup remains weaker than the requested resource contract. The chunk loop does release its STC in finally, calls memory-manager cleanup, and the injected reduction-failure test passes. However, a cleanup exception can still mask the primary inverse/reduction exception, and the outer sequential/parallel/GPU general-exception paths do not uniformly invoke owned-resource cleanup. This is not a newly discovered P1 and does not invalidate the one-STC lifetime proof, but it remains a production-hardening gap. Action: preserve the primary exception if cleanup fails and consolidate idempotent outer cleanup when the next revision is routed.
  3. P2 release evidence — Peak RSS, package build/install, real inverse, and EEGLAB round trip remain unverified. The current mocked allocation tests correctly prove chunk order and one-STC lifetime but cannot establish a process peak-RSS bound. No package build/install or exported-file round trip was run. These are release gates, not reasons by themselves to withhold a corrected feature commit or merge, provided Raven/PI explicitly records them as pre-release requirements.
  4. P2 release/version custody — Capability is explicit, but publication under immutable 0.3.7 remains blocked. RAW_CHUNKING_CAPABILITY="sequential-raw-chunking-v1" is exported and tested. The distribution and CLI still report 0.3.7 despite changed behavior and defaults. A branch commit may precede version selection, and merge may do so if the repository's release process versions later, but no package may be built or published as the existing immutable 0.3.7 identity.
